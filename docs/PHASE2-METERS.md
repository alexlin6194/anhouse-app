# Phase 2:智慧電錶自動抄表 + 儲值斷電型電錶

> 版本 2026-11-21|狀態:**程式已上正式站**(`https://itdc.tw/anhouse`),目前跑模擬電錶;
> 台科電真機待憑證(索取清單見 `docs/PHASE2-TAIKE-REQUEST.md`)

## 這一版做了什麼

| 項目 | 說明 |
|---|---|
| 電錶抽象層 | `MeterAdapter` 介面 + `DevMockMeterAdapter`(模擬)+ `TaikeMeterAdapter`(台科電骨架) |
| 自動抄表 | 每次抄表寫 `meter_readings`(一筆一度數,可追溯),同步更新 `device_meter_state.last_reading` |
| 自動出帳 | 期末後把讀值換算電費寫進該期帳單,重算總額並通知房客 |
| 兩種計費 | 後付型(併入帳單)/ 儲值型(預扣餘額,不足自動斷電) |
| 儲值與斷復電 | `meter_topups` 留存每筆儲值;欠費斷電、儲值後自動復電 |
| 排程 | HTTP 觸發(cPanel Cron 亦可),每小時一次;`CRON_TOKEN` 已設於 `secrets.php` |
| 資料表 | `meter_readings` / `device_meter_state` / `meter_topups` + `bills.reading_source` |

## 計費規則

**後付型**(預設)
```
電費 = (本期讀值 − 上期讀值) × 單價
單價:房源 elec_rate;未設定則用 ELECTRIC_RATE_PER_KWH(目前 NT$5.0/度)
上期讀值:同租約「期間早於本期」的最近一張有讀值的帳單 → 都沒有則用租約 meter_start
```
若房源 `elec_mode='taipower'`,改用台電累進級距(夏月/非夏月自動判斷)。

**儲值型**
```
每次抄表 → 用量 × 單價 從 balance 扣除 → balance ≤ 0 則斷電 + 通知房東與房客
儲值 → 加回 balance → 若原本斷電則自動復電
```

## 自動出帳的四道防護(實測全部有效)

這些規則是被真實情境逼出來的,改動前請確認原因:

| 防護 | 規則 | 為什麼 |
|---|---|---|
| ① 期末才寫 | 自動抄表只在帳單期間(月份)**已結束**後才寫電費 | 月中抄到的是半月用量,寫進整期就錯到底,而且之後會被「不覆蓋」擋住,永遠錯下去 |
| ② 不覆蓋 | 帳單已有電費時,`auto` 來源不覆蓋 | 保護人工調整過的帳單 |
| ③ 不寫已結束租約 | 帳單所屬租約非 `active` 時不自動寫 | 退租電費屬結算爭議,需人工確認加備註 |
| ④ 讀值不倒退 | 本期讀值 < 上期 → 拒寫並提示「請確認電錶是否歸零」 | 換錶、歸零、抄錯都會出現,寫進去就是超額帳單 |

人工寫入(管理端指定讀值)不受 ① 限制,但仍受 ②③④ 檢查。

**上期讀值的取法**(2026-11-21 修正):以「帳單期間」排序,不是 `id` 排序。帳單常會預先建好(下期 draft 先存在),用 `id` 排會抓到未來期間的讀值,導致整期電費算錯。

## 排程設定(正式站)

`CRON_TOKEN` 已寫入 `/domains/itdc.tw/anhouse_private/secrets.php`,`config.php` 讀成常數。

**方式 A:cPanel → Cron Jobs(建議)**
```
wget -q -O /dev/null "https://itdc.tw/anhouse/tools/meter_cron.php?token=<CRON_TOKEN>"
```
頻率:每小時(`0 * * * *`)。抄表是冪等的(同一時間點只留一筆),重複觸發不會重複計費。

**方式 B:PHP CLI**(需主機支援 cron 執行 PHP)
```
0 * * * * /usr/local/bin/php /home/itdctw/domains/itdc.tw/public_html/anhouse/tools/meter_cron.php
```

回應是 JSON,可直接看執行結果:
```json
{"time":"2026-11-21 05:28:27","read":1,"bill":0,"fail":0,
 "items":["301 電錶(模擬):無待寫帳單"]}
```

## 操作(代管/櫃台)

| 想做的事 | 操作 |
|---|---|
| 加裝電錶 | 房源頁 → 加裝裝置 → 類型「智慧電錶」→ 戶別電錶 / 總電錶 → 填序號 |
| 立刻抄一次 | 「⚡ 抄表」按鈕(整戶一次抄完) |
| 寫入帳單 | 電錶卡片 →「寫入帳單」;系統自動挑該戶待繳、且尚無電費的帳單 |
| 改成儲值型 | 卡片上切換計費模式(後付 / 儲值) |
| 儲值 | 儲值型才出現;輸入金額 → 餘額增加,欠費斷電會自動復電 |
| 手動斷/復電 | 卡片上的斷電 / 復電(會寫入事件紀錄) |
| 看歷史 | 卡片顯示最近 6 筆讀值;API `action=readings` 可取 60 筆 |

**權限**:與門鎖相同——屋主、代管管理員、公司管理職可操作,業務唯讀。未登入呼叫 API 一律回 `{"ok":false,"message":"尚未登入"}`。

## 已知限制

1. **目前是模擬電錶**:讀值為系統產生(每小時約 0.35 度遞增),不是真實用電。介面與計費邏輯已驗證,但度數不能用於真實帳單。
2. **台科電真機未接**:缺 `TAIKE_BASE_URL` / `TAIKE_API_KEY` / `TAIKE_API_SECRET`。`TaikeMeterAdapter` 的端點與欄位是依一般慣例寫的骨架,拿到正式 API 文件後需核對(只需改該檔三個方法)。
3. **一戶多錶**目前會各自抄表,但寫帳單時只會用第一台(戶別電錶優先)。若要做「總錶 − 分錶 = 公共用電」需另外設計,尚未實作。
4. **儲值型扣抵用「最近兩筆讀值差」**,若排程停擺數天,恢復後會一次扣較大用量(正確,但金額會嚇到人,建議恢復後先確認)。
